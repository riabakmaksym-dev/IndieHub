---

**Завдання до роботи:**
1. Реалізувати власний REST API веб-сервер на базі Node.js та Express (Варіант 1, максимальна оцінка — 10 балів).
2. Реалізувати безпечну автентифікацію та авторизацію користувачів: реєстрація з валідацією та хешуванням паролів (bcrypt), вхід із генерацією токенів (JWT), отримання профілю поточного користувача через заголовок `Authorization: Bearer <token>` та оновлення даних профілю.
3. Реалізувати кінцеві точки (endpoints) для отримання та фільтрації списку команд, детальної інформації про команду за ідентифікатором, створення нової команди, а також отримання каталогу розробників.
4. Організувати збереження даних на сервері у форматі JSON із підтримкою персистентності між перезапусками.
5. Налаштувати зв'язок між React-застосунком та бекендом: налаштувати проксіювання `/api` у `vite.config.js`, оновити клієнтський сервіс `api.js` на використання Fetch API та забезпечити логіку маршрутизації (перенаправлення неавторизованого користувача на реєстрацію з подальшим переходом на головну сторінку).
6. Провести тестування розробленого API, опублікувати сирцевий код у GitHub-репозиторії та оформити Pull Request.

**Хід роботи:**

### 1. Архітектура та налаштування структури серверної частини
Для реалізації бекенду в корені проєкту було створено ізольовану директорію `server/` із чітким модульним розділенням відповідальності:
* `server/index.js` — точка входу та запуск HTTP-сервера на порту 5000.
* `server/app.js` — налаштування Express-додатка, підключення CORS, парсера JSON, логування запитів та глобальної обробки помилок.
* `server/storage.js` — модуль управління станом сховища даних із збереженням у файл `server/data/db.json`.
* `server/middleware/auth.js` — проміжне програмне забезпечення для перевірки та валідації JWT-токенів (`authMiddleware`, `optionalAuthMiddleware`).
* `server/routes/` — маршрути для відповідних сутностей: `auth.js` (авторизація), `teams.js` (команди), `developers.js` (розробники).
* `server/test-inmemory.js` — модульні та інтеграційні тести перевірки працездатності всіх кінцевих точок.

*(Рис 1. Структура папки server)*

### 2. Реалізація автентифікації та авторизації (JWT + bcrypt)
Безпеку облікових записів користувачів реалізовано у модулі `server/routes/auth.js`:
* `POST /api/auth/register` — здійснює валідацію вхідних даних (перевірка унікальності email та нікнейму, довжина пароля від 6 символів), хешує пароль за допомогою бібліотеки `bcryptjs` та створює профіль користувача, повертаючи згенерований `jsonwebtoken` (JWT).
* `POST /api/auth/login` — перевіряє відповідність введеного пароля збереженому хешу через `bcrypt.compare` та видає підписаний токен терміном дії 7 днів.
* `GET /api/auth/me` — захищений маршрут, що через `authMiddleware` дешифрує токен із заголовка `Authorization: Bearer <token>`, знаходить користувача в базі та повертає його дані без конфіденційного пароля.
* `PUT /api/auth/profile` — оновлення ролі, списку навичок та біографії користувача.

### 3. Реалізація ендпоінтів для отримання та збереження даних
Для взаємодії з командами та розробниками створено наступні маршрути:
* `GET /api/teams` — повертає список створених команд із можливістю динамічної фільтрації за жанром (`genre`), рушієм (`engine`), необхідною роллю (`role`), статусом (`status`) або текстовим пошуком (`q`).
* `GET /api/teams/:id` — повертає вичерпні дані про конкретну команду та список її учасників.
* `POST /api/teams` — додає нову команду до сховища з автоматичним призначенням автора лідером команди.
* `GET /api/developers` — каталог фахівців із фільтрацією за напрямками та стеком технологій.

*(Рис 2. Маршрути та сервіси бекенду)*

### 4. Інтеграція з клієнтським застосунком (React + Vite)
Для безперешкодної взаємодії фронтенду з Express-сервером:
1. У `vite.config.js` налаштовано зворотне проксіювання (Reverse Proxy): усі запити з префіксом `/api` автоматично скеровуються локальним сервером розробки Vite на `http://localhost:5000`. Це запобігає блокуванню запитів політикою безпеки CORS.
2. Клієнтський модуль `src/services/api.js` переведено на використання нативного Fetch API. Він здійснює реальні мережеві запити, централізовано зберігає отриманий JWT-токен у `localStorage` та автоматично додає заголовок `Authorization` до наступних викликів. Також передбачено механізм відмовостійкості на випадок відсутності активного сервера.
3. У `src/App.jsx` оновлено логіку клієнтської маршрутизації: якщо користувач неавторизований, при відкритті застосунку його автоматично перенаправляє на сторінку реєстрації (`/register`), а після успішного створення акаунту — на Головну сторінку (`/`), відкриваючи доступ до всіх розділів платформи.
