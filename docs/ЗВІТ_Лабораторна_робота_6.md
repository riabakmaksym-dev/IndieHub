## 1. Мета роботи
Реалізувати повнофункціональний REST API бекенд на платформі **Node.js** з використанням фреймворку **Express** для забезпечення отримання необхідних даних клієнтською частиною (React-застосунок **IndieHub**), створення нових сутностей, оновлення профілю та безпечної автентифікації й авторизації користувачів з використанням JWT-токенів та хешування паролів.

## 4. Опис реалізованих кінцевих точок (API Endpoints)

### 4.1. Авторизація (`/api/auth`)

| Метод | Маршрут | Опис | Захист |
|---|---|---|---|
| `POST` | `/api/auth/register` | Реєстрація нового акаунта. Хешує пароль через bcrypt, створює профіль та повертає JWT-токен. | Публічний |
| `POST` | `/api/auth/login` | Вхід у систему. Звіряє хеш пароля, генерує та повертає JWT-токен. | Публічний |
| `GET` | `/api/auth/me` | Отримання профілю поточного автентифікованого користувача. | `Bearer Token` |
| `PUT` | `/api/auth/profile` | Оновлення біографії, ролі та навичок користувача. | `Bearer Token` |

**Приклад коду автентифікації (`server/routes/auth.js`):**
```javascript
router.post('/login', async (req, res) => {
  const { email, password } = req.body;
  if (!email || !password) {
    return res.status(400).json({ error: 'Будь ласка, вкажіть email та пароль' });
  }

  const user = storage.findUserByEmail(email);
  if (!user) {
    return res.status(401).json({ error: 'Невірний email або пароль' });
  }

  const isMatch = await bcrypt.compare(password, user.password);
  if (!isMatch) {
    return res.status(401).json({ error: 'Невірний email або пароль' });
  }

  const token = jwt.sign({ id: user.id, email: user.email }, JWT_SECRET, { expiresIn: '7d' });
  return res.json({ token, user: sanitizeUser(user) });
});
```

## 5. Middleware автентифікації (`server/middleware/auth.js`)

Для захисту кінцевих точок створено middleware `authMiddleware`, який витягує токен із заголовка `Authorization: Bearer <token>`, перевіряє його валідність через `jwt.verify` та прикріплює об'єкт користувача до `req.user`:

```javascript
export const authMiddleware = (req, res, next) => {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Необхідна авторизація. Токен відсутній.' });
  }

  const token = authHeader.split(' ')[1];
  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    const user = storage.findUserById(decoded.id);
    if (!user) {
      return res.status(401).json({ error: 'Користувача за токеном не знайдено.' });
    }
    req.user = user;
    req.userId = user.id;
    next();
  } catch {
    return res.status(401).json({ error: 'Недійсний або прострочений токен авторизації.' });
  }
};
```

## 6. Інтеграція з клієнтською частиною (React + Vite)

### 6.1. Налаштування проксі у `vite.config.js`:
Усі запити фронтенду на відносний шлях `/api` перенаправляються Vite на локальний Express-сервер (порт 5000):
```javascript
export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:5000',
        changeOrigin: true
      }
    }
  }
});
```

### 6.2. Клієнтський сервіс `src/services/api.js`:
Сервіс здійснює реальні HTTP-запити за допомогою Fetch API, автоматично прикріплюючи заголовок авторизації у разі наявності збереженого токена, та централізовано обробляє помилки відповіді сервера.
